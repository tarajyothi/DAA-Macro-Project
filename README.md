## Objective
To apply the main algorithm-design paradigms taught in DAA – algorithm analysis, greedy method, dynamic programming, backtracking and branch and bound – by implementing one representative problem from each unit, analysing its complexity, and explaining its working with a visualization that matches the code.

## Technologies Used
* **Python 3** – Units I, III, V (with `matplotlib` for the Unit I chart)
* **C++17** – Unit II
* **Java (JDK 8+)** – Unit IV
* **AI-assisted visualization** – each `Visualization.png` was produced from the prompt stored in that unit's `Prompt.txt`, using AI-written Python/matplotlib code driven by the actual algorithm results
* **PowerPoint** – classroom presentation in `PPT/`

## Learning Outcomes
* Compare algorithms using asymptotic notation and recurrence relations (Unit I).
* Design and justify greedy strategies, and prove optimality by the greedy-choice property (Unit II).
* Formulate problems as DP states with a recurrence, including bit-mask subset states (Unit III).
* Use backtracking with constraint checks and state space trees (Unit IV).
* Apply bounding functions and pruning in branch and bound (Unit V).
* Present algorithm behaviour with clear pseudocode, output and visualizations.

## AI Visualization Approach
Every project folder contains the same five ingredients:
1. **Algorithm** – a working, commented implementation in the unit's language.
2. **Pseudocode** – written in the project's `README.md`.
3. **AI prompt** – the exact visualization prompt in `Prompt.txt`.
4. **Generated visualization** – `Visualization.png`, drawn from the prompt and built from the algorithm's real results (for example, the TSP and Knapsack figures are generated by importing the project's own Python functions, and the N-Queens tree is checked against the Java counters: 60 placements, 2 solutions).
5. **README** – description, problem statement, output, complexity analysis, learning outcomes and run instructions.

The Unit I chart is explicitly labelled as *theoretical* growth of n log n and n²; it does not claim to be measured runtime.

## Conclusion
The five projects together cover the core design techniques of DAA. Sorting analysis shows how complexity classes separate as n grows; greedy sequencing shows a locally optimal rule that yields a global optimum; Held–Karp shows how DP replaces O(n!) enumeration; N-Queens shows pruning by constraint checking; and Branch and Bound shows pruning with bounds. Each visualization is tied directly to its code and output, making the repository suitable for faculty review and classroom presentation.
